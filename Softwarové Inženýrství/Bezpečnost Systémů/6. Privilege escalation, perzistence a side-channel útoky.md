První přístup do systému často není konečný cíl. Útočník může začít jako běžný uživatel webové aplikace, omezený shell, kompromitovaný proces nebo účet s nízkými právy. Další krok je získat lepší pozici, vydržet v systému a případně se šířit dál.

# Privilege escalation

**Privilege escalation** znamená zvýšení efektivních práv útočníka. U vertikální eskalace jde o přechod z běžného účtu na administrátora nebo root. U horizontální eskalace jde o přístup k jinému účtu nebo objektu se srovnatelnými právy, typicky k datům jiného uživatele.

Vertikální eskalace v operačním systému často využívá špatnou konfiguraci. Proces běží jako root, zapisuje do souboru, který může měnit běžný uživatel. Cron spouští skript z adresáře, kam útočník zapisuje. SUID binárka dovolí spustit shell. Kernel má zranitelnost, která dovolí přepsat credential struktury procesu.

**SUID binárka** je program, který se po spuštění chová, jako by ho spustil vlastník souboru. Pokud je vlastníkem root a program má chybu, běžný uživatel může získat root práva. **Credential struktury procesu** jsou interní data kernelu o tom, pod jakým uživatelem a s jakými právy proces běží; jejich poškození nebo přepsání může změnit efektivní oprávnění.

Horizontální eskalace je častá ve webových aplikacích. Uživatel změní `userId=123` na `userId=124` a server mu vrátí cizí fakturu. UI sice tlačítko nezobrazovalo, ale backend oprávnění neověřil. To není UI bug, to je autorizační selhání.

Obrana stojí na least privilege, oddělení účtů, bezpečné konfiguraci sudo/SUID, pravidelných patchích, kontrole zapisovatelných cest a důsledné autorizaci na serveru.

# Perzistence

**Perzistence** je schopnost zůstat v systému i po restartu, odhlášení nebo výpadku spojení. Útočník si nechce každý den znovu dobývat stejný server. Chce zadní dveře.

Na Linuxu se perzistence často dělá přes cron, systemd service, shell startup soubory, SSH authorized_keys, upravené knihovny, LD_PRELOAD, kernel moduly nebo změnu legitimních skriptů. Na Windows přes Run keys v registrech, plánovač úloh, služby, WMI event subscription nebo DLL hijacking.

**Shell startup soubory** jako `.bashrc` nebo `.profile` se spouštějí při otevření shellu. **SSH `authorized_keys`** určuje, které veřejné klíče se smí přihlásit na účet. **LD_PRELOAD** umí v Linuxu vynutit načtení knihovny před ostatními, takže útočník může změnit chování programu. **Run keys** jsou položky registrů Windows spouštěné při startu nebo přihlášení. **WMI event subscription** je mechanismus Windows pro spuštění akce při určité události. **DLL hijacking** zneužívá situaci, kdy program načte útočníkovu knihovnu místo legitimní.

Perzistence nemusí být technicky složitá. Přidání vlastního SSH klíče je jednodušší než rootkit a často stačí. Právě proto je důležité sledovat změny v autorizačních souborech, nově vzniklé služby a neobvyklé scheduled tasks.

Rootkit je pokročilejší forma perzistence a skrývání. Může měnit chování systému tak, aby procesy, soubory nebo síťová spojení nebyly vidět běžnými nástroji. Obrana vyžaduje integritní kontroly, EDR, boot integrity a ideálně porovnání zvenčí.

# Reverse shell a bind shell

Po získání přístupu útočník často potřebuje interaktivní ovládání. **Bind shell** otevře port na oběti a čeká, až se útočník připojí. Problém je firewall: příchozí spojení bývá blokované. **Reverse shell** funguje opačně. Oběť se připojí ven k útočníkovi. To často projde, protože odchozí provoz je povolený volněji.

To je důležité architektonicky. Ochrana příchozích portů pokrývá jen jednu část problému. Musíme sledovat i odchozí spojení. Server, který nikdy nemá komunikovat do internetu, by neměl mít volný egress.

# Side-channel útoky

**Side-channel útok** nezneužívá logickou chybu v algoritmu, ale vedlejší fyzikální projev jeho běhu. Program může matematicky správně šifrovat, ale jeho časování, cache přístupy nebo spotřeba mohou prozradit klíč.

**Timing attack** měří čas odpovědi. Pokud porovnávání tajného tokenu končí při první neshodě, útočník může postupně odhadovat správné znaky podle toho, jak dlouho porovnání trvalo. Obrana je constant-time porovnání.

**Cache attack** využívá sdílenou cache CPU. Útočník měří, které cache line byly použité, a z toho odvozuje chování oběti. Spectre a Meltdown ukázaly, že spekulativní exekuce a mikroarchitektura nejsou jen výkonové detaily, ale bezpečnostní hranice.

**Power analysis** sleduje spotřebu zařízení. U čipových karet nebo embedded zařízení může spotřeba při kryptografii prozrazovat bity klíče. **Electromagnetic analysis** používá elektromagnetické vyzařování.

Mentální model: když neslyším rozhovor za zdí, ale slyším kroky a cvakání vypínačů, mohu přesto odvodit, co se v místnosti děje. Side-channel je přesně tohle.

# Obrana proti side-channelům

Obrana je těžká, protože bojuje s fyzikou a implementací. U kryptografie se používají constant-time algoritmy, masking, randomizace, izolace procesů, vypnutí sdílení některých prostředků, hardwarové mitigace a pečlivé knihovny. V aplikacích je důležité nepoužívat vlastní kryptografii a nespoléhat se na naivní porovnávání tajných hodnot.

# Co říct u státnic

Privilege escalation zvyšuje práva nebo rozsah přístupu. Perzistence umožňuje návrat po restartu nebo ztrátě session. Reverse shell obchází blokovaná příchozí spojení tím, že oběť naváže odchozí spojení. Side-channel útoky využívají čas, cache, spotřebu nebo jiné vedlejší projevy výpočtu; obrana vyžaduje constant-time implementace a izolaci sdílených zdrojů.
