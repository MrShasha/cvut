## Státnicové minimum

Toto je krátký checklist podle oficiálních okruhů BE4M36SWA. Není to náhrada celých poznámek, ale rychlá kontrola před ústní zkouškou.

- Umět definovat software architecture jako nejvyšší strukturu systému: hlavní prvky, jejich odpovědnosti, vztahy, komunikaci, nasazení a vazbu na quality attributes.
- Umět vysvětlit rozdíl mezi architecture a design: architecture řeší komponenty a systémová rozhodnutí, design řeší třídy, rozhraní, metody a implementační patterns.
- Umět vysvětlit, proč je SWA důležitá: řízení složitosti, vývoj, údržba, komunikace stakeholderů, testovatelnost, škálování, bezpečnost, evoluce a kontrola technického dluhu.
- Znát základní design guidelines: KISS, YAGNI, DRY, separation of concerns, high cohesion, loose coupling, encapsulation, dependency inversion, explicit architecture decisions a dokumentace.
- Umět popsat Kruchten's 4+1 View Model: logical, process, development, physical view a scenarios jako +1 view.
- Umět přiřadit Kruchtenovy views k UML: logical view hlavně class/state diagram, process view sequence/activity diagram, physical view deployment diagram, scenarios use-case/sequence diagram; development view package/component/module diagram.
- Umět definovat architectural style, architectural pattern a design pattern a vysvětlit rozdíly mezi nimi.
- Znát hlavní styly: layered, modular monolith, hexagonal/ports and adapters, microkernel, client-server, SOA, event-driven architecture, microservices, pipes and filters, peer-to-peer, space-based architecture.
- Umět detailně rozebrat alespoň jeden styl, ideálně layered architecture nebo microservices: princip, typické komponenty, výhody, nevýhody, použití, pasti.
- Umět vysvětlit design pattern: pojmenované, obecně použitelné řešení opakujícího se design problému; struktura pattern name/problem/solution/consequences.
- Znát základní typy GoF patterns: creational, structural, behavioral; umět uvést příklady jako Factory, Builder, Singleton, Adapter, Facade, Proxy, Strategy, Observer, Command, State.
- Znát enterprise patterns: DTO, DAO, Repository, Unit of Work, Lazy Load, optimistic/pessimistic locking, IoC, Dependency Injection.
- Umět vysvětlit antipattern: opakované špatné řešení, které vypadá užitečně, ale dlouhodobě škodí. Uvést Big Ball of Mud, distributed monolith, shared database, no API versioning, chatty services.
- Umět definovat microservice architecture: kolekce malých, loosely coupled, independently deployable služeb organizovaných kolem business capabilities a vlastněných malými týmy.
- Umět porovnat microservices a monolith: deployment, development, debugging, testing, transakce, data consistency, škálování, team autonomy, DevOps nároky.
- Umět říct, kdy je lepší monolith/modular monolith a kdy microservices. Nepoužívat tvrzení 'microservices jsou vždy lepší'.
- Znát microservice patterns: decomposition by business capability/DDD subdomain, database per service, API Gateway, Service Discovery, Saga, Outbox, Event Sourcing, CQRS, API Composition, Circuit Breaker, Bulkhead, Retry with backoff, Timeout, Correlation ID, Observability.
- Znát microservice best practices: design for failure, idempotency, eventual consistency, contract compatibility, CI/CD, monitoring/logging/tracing, twelve-factor apps, reactive principles.
- Znát microservice antipatterns: microservices as the goal, trying to fly before you can walk, distributed monolith, wrong cuts, microservice per entity, shared persistence, long synchronous chain, retry storm, event soup, no observability, too many technologies.
- Umět vysvětlit, že architekturu nelze hodnotit absolutně jako dobrou/špatnou. Hodnotí se podle kontextu, stakeholder concerns, business drivers, constraints a quality attributes.
- Umět definovat quality attribute a quality requirement; požadavek musí být měřitelný/testovatelný a mít kontext.
- Znát quality attribute scenario: stimulus source, stimulus, environment, artifact, response, response measure.
- Znát různé perspektivy kvality: design/system perspective, developer perspective, user/operations perspective.
- Znát ISO/IEC 25010: functional suitability, performance efficiency, compatibility, usability, reliability, security, maintainability, portability.
- Umět vysvětlit ATAM: Architecture Trade-off Analysis Method; vstupy business drivers, architecture, quality attributes, scenarios; výstupy risks, non-risks, sensitivity points, trade-offs, risk themes.
- Umět uvést praktický příklad trade-offu: microservices zvyšují deployment autonomy a škálovatelnost, ale zvyšují distributed complexity; silnější security může snížit performance; cache zlepšuje latency, ale komplikuje consistency.
