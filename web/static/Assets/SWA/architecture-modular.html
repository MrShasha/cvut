Software architecture

Modular monolith

Jeden deployment, ale uvnitř jasné business moduly.
request: Uživatel stále volá jednu aplikaci; UI je uvnitř modular monolitu.
Princip

Modular monolith drží nízkou provozní komplexitu monolitu, ale zavádí pevné hranice mezi moduly.

Kdy použít
  • rostoucí systém
  • tým ještě nepotřebuje nezávislé deploymenty
  • dobrý mezikrok před microservices
Pozor na
  • hranice se musí aktivně hlídat
  • stále jeden deployment
  • při špatné disciplíně vznikne Big Ball of Mud
Quality attributes
low ops costbusiness modulesgood migration path
Flow
  1. 1Uživatel stále volá jednu aplikaci.
  2. 2UI a application shell jsou součást stejného deployable unit.
  3. 3Shell vybere správný business modul.
  4. 4Moduly nesahají do cizích interních detailů.
  5. 5Deployment zůstává jeden.
