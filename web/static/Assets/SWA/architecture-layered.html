Software architecture

Layered architecture

Technické vrstvy jsou seřazené shora dolů: UI/API, application, domain, persistence.
HTTP: Request vstoupí do presentation vrstvy.
Princip

Každá vrstva má jinou odpovědnost. Závislosti typicky směřují dolů a výšší vrstva používá službu nižší vrstvy.

Kdy použít
  • enterprise CRUD aplikace
  • framework-driven backend
  • tým potřebuje jednoduchou strukturu
Pozor na
  • změna často prochází více vrstvami
  • může vzniknout anemický domain model
  • cross-cutting concerns se špatně umisťují
Quality attributes
clear structuretestable layersfamiliar pattern
Flow
  1. 1Request vstoupí do presentation vrstvy.
  2. 2Application vrstva řídí use case.
  3. 3Domain vrstva provádí business pravidla.
  4. 4Persistence vrstva načítá nebo ukládá data.
  5. 5Databáze je za persistence vrstvou.
