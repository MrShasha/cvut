## High-level přehled

Stín vzniká, když bod na povrchu objektu nemá přímou viditelnost ke světelnému zdroji. Všechny algoritmy tento test řeší různými způsoby — buď přímo z pohledu bodu (objektový prostor), nebo nepřímo přes předpočítanou strukturu ze světla (obrazový prostor).

Státnicová osnova vyžaduje dvě metody: **ray-cast shadows** (test viditelnosti světla stínovým paprskem) a **shadow map** (Williams 1978). **Projektivní stíny** podle Blinna jsou jiná metoda probíraná v přednášce; nejsou synonymem ray-cast shadows. Shadow volumes (Crow 1977) jsou v přednášce jako další kontext.

## 1. Ray-cast shadows

### Princip

Pro stínovaný bod `P` testujeme, zda je světelný zdroj přímo viditelný. Z bodu vyšleme **stínový paprsek** směrem ke světlu:

```text
d = L - P
t_max = |d|
R(t) = P + εN + t · normalize(d)
```

- Pokud paprsek protne jiný objekt pro `0 < t < t_max`, světlo je zakryté a bod je ve stínu.
- Pokud žádný takový průsečík neexistuje, přímý příspěvek světla se započítá.
- Posun `εN` brání tomu, aby paprsek kvůli numerické chybě okamžitě zasáhl povrch, ze kterého vychází.
- Pro směrové světlo je směr konstantní a `t_max = ∞`.

Viditelnost lze zapsat binární funkcí:

```text
V(P,L) = 0  ... světlo zakryté
V(P,L) = 1  ... světlo viditelné

L_direct = V(P,L) · fr · Li · max(N·L, 0)
```

### Algoritmus

```text
pro každý viditelný bod P:
  pro každý světelný zdroj:
    vytvoř stínový paprsek z P ke světlu
    pokud před světlem existuje průsečík:
      příspěvek tohoto světla = 0
    jinak:
      vyhodnoť lokální osvětlení
```

### Vlastnosti

- Přesné ostré stíny pro bodové nebo směrové zdroje.
- Přirozeně funguje se zakřivenými přijímači i se self-shadowingem.
- Plošný zdroj se vzorkuje více stínovými paprsky; podíl nezakrytých vzorků vytvoří penumbru a měkký stín.
- Naivní test stojí `O(N)` průsečíků na paprsek; BVH, kd-strom nebo octree jej typicky sníží přibližně na `O(log N)` pro dobře vyváženou strukturu.
- U statických scén lze výsledky předpočítat do **lightmapy**; přednáška tímto způsobem ukazuje i „baked" měkké stíny.

## 2. Projektivní stíny — Blinn 1988

### Princip

Geometrická projekce stínícího objektu na rovinu přijímače ve směru světla. Každý vrchol `p` se promítne ze světla `L` na rovinu přijímače.

> [!note] 🧠 Matějův příprdek — jak vznikne projektivní stín
> Pro každý vrchol objektu `v`:
>
> 1. Veď přímku ze světla `l` přes vrchol `v`.
> 2. Najdi průsečík této přímky s podlahou.
> 3. Průsečík `p` je odpovídající vrchol stínu.
>
> Když takto promítneš všechny vrcholy, dostaneš na podlaze zploštělou kopii objektu. Tu vykreslíš tmavou průhlednou barvou jako stín.
> ![[projektivní stíný.png]]

### Odvození pro rovinu y=0

Přímka skrz světlo a vrchol: `bod = L + t·(p - L)`

Podmínka `y = 0`:

```
t = ly / (ly - py)
```

Stínové souřadnice:

```
sx = lx + t·(px - lx)
sy = 0
sz = lz + t·(pz - lz)
```

### 4×4 projektivní matice M

Celý výpočet se zabalí do matice v homogenních souřadnicích. Přidá se do pohledové transformace, objekt se vykreslí znovu — zploštělý na rovinu přijímače s tmavým blendingem.

Pro rovinu v homogenním tvaru `π = (a,b,c,d)` a homogenní polohu/směr světla `l = (lx,ly,lz,lw)`:

```
M = (πᵀl)·I - l·πᵀ
```

### Algoritmus

```
1. Vykresli scénu (plné osvětlení)
2. Pro každý polygon přijímače (podlaha, zeď):
   a. Spočítej projekční matici M
   b. Přidej M do pohledové transformace
   c. Vykresli stínující objekt s tmavým blendingem
```

### Artefakty a řešení

|Problém|Příčina|Řešení|
|---|---|---|
|**Antishadow**|objekt za rovinou přijímače (t < 0)|stencil buffer|
|**False shadow**|objekt za světlem (0 ≤ t < 1, špatná strana)|stencil buffer|
|**Z-fighting**|stínový polygon na stejné rovině jako přijímač|stencil buffer|
|**Double blending**|pixel ztmaven vícekrát při více světlech|stencil — každý pixel max 1×|

**Stencil buffer algoritmus:**

```
1. Vykresli přijímač → zapiš 1 do stencilu
2. Vykresli stínový polygon:
   - Stencil test: pouze kde stencil == 1
   - Po vykreslení: nastav stencil na 0
```

### Vlastnosti

```
✓ Velmi rychlé, jednoduché na implementaci
✓ Žádné self-shadowing
✓ GLQuake — první hra která to implementovala
✗ Pouze rovinné přijímače (podlaha, zeď)
✗ Falešné stíny (nutný stencil)
✗ Pouze polygonální objekty
✗ Pouze ostré stíny
```

## 3. Shadow Map — Williams 1978

### Princip

Obrazový prostor. Ze světla se předpočítá hloubková mapa — textura vzdáleností nejbližších povrchů. Při renderování z kamery se každý bod transformuje do souřadnic světla a porovná s uloženou hodnotou.

### Algoritmus (2 průchody)

```
PRŮCHOD 1 — ze světla:
  Vykresli scénu z pozice světla
  Ulož z-buffer → shadow mapa H

PRŮCHOD 2 — z kamery:
  Vykresli scénu z pozice kamery
  Pro každý fragment se světovou polohou P:
    1. Transformuj P view-projekční maticí světla, proveď perspektivní dělení
       a převeď výsledek do souřadnic shadow mapy → [x,y,z]
    2. A = H[x,y]   ← nejbližší povrch viditelný ze světla
    3. B = z         ← projektovaná hloubka bodu ve stejné reprezentaci jako H
    4. if (A < B) → VE STÍNU
       else       → OSVĚTLEN
```

- Každý bod promítneme do prostoru světla a porovnáme jeho hloubku se shadow mapou.

### Artefakty

**1. Perspektivní aliasing**

- Příčina: texely shadow mapy rovnoměrně rozložené, ale kamera vidí blízké objekty větší → blízko kamery málo texelů na pixel
- Řešení: **Perspective Shadow Maps** (Stamminger & Drettakis) — shadow mapa se vytvoří až po perspektivním promítání scény → automaticky vyšší rozlišení blízko kamery

**2. Projekční aliasing**

- Příčina: přijímač skoro rovnoběžný se směrem světla → jeden texel pokrývá velkou plochu
- Řešení: není přímé — využívá fyziku: `I = IL · max(dot(L,N), 0)` → takový povrch je stejně skoro tmavý → artefakty nejsou vidět
- Doporučení: malý ambient term, difuzní term artefakty přirozeně zakrývá

**3. Self-shadow aliasing (surface acne)**

- Příčina: numerické nepřesnosti při porovnání A a B pro stejný povrch → povrch vrhá stín sám na sebe
- Řešení: **bias** — malé posunutí B před porovnáním (`B = z - ε`)
- Woo [1992]: do shadow mapy uložit průměr vzdáleností dvou nejbližších povrchů

**4. PCF — Percentage Closer Filtering**

- Filtrace aliasovaných hran stínu; vytváří měkčí přechod, ale sama o sobě není fyzikálně správným modelem plošného světla
- Nelze filtrovat hodnoty shadow mapy přímo (průměr hloubek nedává smysl)
- Filtruje se výsledek binárního testu (osvětlen/stín) přes okolní texely
- NVIDIA HW podpora: 2×2 PCF

### Vlastnosti

```
✓ Rychlý — jeden hloubkový průchod navíc pro každou mapu světla
✓ Po vytvoření mapy je test stínu pro fragment konstantně drahý texture lookup
✓ Libovolné přijímače (zakřivené povrchy!)
✓ Lze implementovat v HW (texture mapping)
✓ Self-shadowing (s biasem)
✗ Aliasing (obrazový prostor, konečné rozlišení)
✗ Bodové světlo vyžaduje cubemap (6 pohledů); směrová a spot světla používají jednu projekci
✗ Bias tweaking (light leaking vs. surface acne)
```

## Srovnání metod

||Ray-cast shadows|Projektivní stíny|Shadow map|
|---|---|---|---|
|Princip|paprsek z bodu ke světlu|zploštění casteru na rovinu|hloubková mapa ze světla|
|Prostor|objektový|objektový/projektivní|obrazový|
|Přijímače|libovolné|pouze roviny|libovolné|
|Přesnost|geometrická, omezená numerikou|geometrická projekce|závislá na rozlišení|
|Self-shadow|ano s `ε`|ne|ano s biasem|
|Měkké stíny|ano, vzorkováním plošného světla|jen aproximace|aproximace/rozšíření|
|Hlavní cena|průsečíkové testy|opakované vykreslení casteru|hloubkový průchod ze světla|
|Akcelerace|BVH / kd-strom|rasterizace + stencil|textura + z-buffer|
