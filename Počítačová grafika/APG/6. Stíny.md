## High-level přehled

Stín vzniká, když bod na povrchu objektu nemá přímou viditelnost ke světelnému zdroji. Všechny algoritmy tento test řeší různými způsoby — buď přímo z pohledu bodu (objektový prostor), nebo nepřímo přes předpočítanou strukturu ze světla (obrazový prostor).

Státnicová osnova definuje dvě metody: **ray cast shadows** (= projektivní stíny, Blinn 1988) a **shadow map** (Williams 1978). Shadow volumes (Crow 1977) nejsou v okruzích, ale jsou v přednášce jako kontext.

## 1. Projektivní stíny (Ray Cast Shadows) — Blinn 1988

### Princip

Geometrická projekce stínícího objektu na rovinu přijímače ve směru světla. Každý vrchol `p` se promítne ze světla `L` na rovinu přijímače.

### Odvození pro rovinu y=0

Přímka skrz světlo a vrchol: `bod = L + t·(p - L)`

Podmínka `y = 0`:

```
t = ly / (ly - py)
```

Stínové souřadnice:

```
sx = lx + t·(px - lx)
sy = 0
sz = lz + t·(pz - lz)
```

### 4×4 projektivní matice M

Celý výpočet se zabalí do matice v homogenních souřadnicích. Přidá se do pohledové transformace, objekt se vykreslí znovu — zploštělý na rovinu přijímače s tmavým blendingem.

Pro libovolnou rovinu `n·x + d = 0` a světlo `l`:

```
M = (n·l + d)·I - l·nᵀ   (v homogenních souřadnicích 4×4)
```

### Algoritmus

```
1. Vykresli scénu (plné osvětlení)
2. Pro každý polygon přijímače (podlaha, zeď):
   a. Spočítej projekční matici M
   b. Přidej M do pohledové transformace
   c. Vykresli stínující objekt s tmavým blendingem
```

### Artefakty a řešení

|Problém|Příčina|Řešení|
|---|---|---|
|**Antishadow**|objekt za rovinou přijímače (t < 0)|stencil buffer|
|**False shadow**|objekt za světlem (0 ≤ t < 1, špatná strana)|stencil buffer|
|**Z-fighting**|stínový polygon na stejné rovině jako přijímač|stencil buffer|
|**Double blending**|pixel ztmaven vícekrát při více světlech|stencil — každý pixel max 1×|

**Stencil buffer algoritmus:**

```
1. Vykresli přijímač → zapiš 1 do stencilu
2. Vykresli stínový polygon:
   - Stencil test: pouze kde stencil == 1
   - Po vykreslení: nastav stencil na 0
```

### Vlastnosti

```
✓ Velmi rychlé, jednoduché na implementaci
✓ Žádné self-shadowing
✓ GLQuake — první hra která to implementovala
✗ Pouze rovinné přijímače (podlaha, zeď)
✗ Falešné stíny (nutný stencil)
✗ Pouze polygonální objekty
✗ Pouze ostré stíny
```

## 2. Shadow Map — Williams 1978

### Princip

Obrazový prostor. Ze světla se předpočítá hloubková mapa — textura vzdáleností nejbližších povrchů. Při renderování z kamery se každý bod transformuje do souřadnic světla a porovná s uloženou hodnotou.

### Algoritmus (2 průchody)

```
PRŮCHOD 1 — ze světla:
  Vykresli scénu z pozice světla
  Ulož z-buffer → shadow mapa H

PRŮCHOD 2 — z kamery:
  Vykresli scénu z pozice kamery
  Pro každý pixel [u,v] s hloubkou w:
    1. Transformuj [u,v,w] do souřadnic světla → [x,y,z]
    2. A = H[x,y]   ← nejbližší povrch viditelný ze světla
    3. B = z         ← vzdálenost tohoto bodu od světla
    4. if (A < B) → VE STÍNU
       else       → OSVĚTLEN
```

### Artefakty

**1. Perspektivní aliasing**

- Příčina: texely shadow mapy rovnoměrně rozložené, ale kamera vidí blízké objekty větší → blízko kamery málo texelů na pixel
- Řešení: **Perspective Shadow Maps** (Stamminger & Drettakis) — shadow mapa se vytvoří až po perspektivním promítání scény → automaticky vyšší rozlišení blízko kamery

**2. Projekční aliasing**

- Příčina: přijímač skoro rovnoběžný se směrem světla → jeden texel pokrývá velkou plochu
- Řešení: není přímé — využívá fyziku: `I = IL · max(dot(L,N), 0)` → takový povrch je stejně skoro tmavý → artefakty nejsou vidět
- Doporučení: malý ambient term, difuzní term artefakty přirozeně zakrývá

**3. Self-shadow aliasing (surface acne)**

- Příčina: numerické nepřesnosti při porovnání A a B pro stejný povrch → povrch vrhá stín sám na sebe
- Řešení: **bias** — malé posunutí B před porovnáním (`B = z - ε`)
- Woo [1992]: do shadow mapy uložit průměr vzdáleností dvou nejbližších povrchů

**4. PCF — Percentage Closer Filtering**

- Softwarové rozostření hran stínu
- Nelze filtrovat hodnoty shadow mapy přímo (průměr hloubek nedává smysl)
- Filtruje se výsledek binárního testu (osvětlen/stín) přes okolní texely
- NVIDIA HW podpora: 2×2 PCF

### Vlastnosti

```
✓ Rychlý — pouze jeden extra průchod
✓ Nezávislý na složitosti scény
✓ Libovolné přijímače (zakřivené povrchy!)
✓ Lze implementovat v HW (texture mapping)
✓ Self-shadowing (s biasem)
✗ Aliasing (obrazový prostor, konečné rozlišení)
✗ Problematický pro všesměrová světla (cube shadow map)
✗ Pouze bodové světelné zdroje
✗ Bias tweaking (light leaking vs. surface acne)
```

## Srovnání obou metod

||Projektivní stíny|Shadow Map|
|---|---|---|
|Prostor|objektový|obrazový|
|Přijímače|pouze roviny|libovolné|
|Přesnost|exaktní (geometrie)|závislá na rozlišení|
|Rychlost|velmi rychlá|rychlá (1 extra průchod)|
|Self-shadow|ne|ano (s biasem)|
|Světelné zdroje|bodové|bodové|
|HW akcelerace|stencil buffer|texture + z-buffer|
