## 1. Kreslení čar

> **Co to je:** Digitalizace matematicky nekonečně tenké čáry na diskrétní mřížku pixelů — vzorkování spojité funkce po 1pixelovém kroku podél hlavní osy.

### 1.1 DDA (Digital Differential Analyzer)

> **Jednovětá podstata:** DDA rasterizuje úsečku inkrementálním přičítáním směrnice `k` v plovoucí desetinné čárce — hlavní osa postupuje po celých krocích, vedlejší osa se zaokrouhluje.

**Princip:**

- Směrnice `k = Δy/Δx` (nebo `1/k` pokud `|k| > 1` — pak je hlavní osou y)
- Na každém kroku: `x_{i+1} = x_i + 1`, `y_{i+1} = y_i + k`
- Výsledné souřadnice se zaokrouhlí na int → `setPixel(round(x), round(y))`

**Zpracování endpointů:**

1. Zaokrouhlení vstupních souřadnic
2. Určení hlavní osy podle `|k|` (≤1 → osa x, >1 → osa y)
3. Orientace: vždy zleva doprava (nebo zespodu nahoru)

**Problém:** Reálná aritmetika (float) → pomalé, zaokrouhlovací chyby.

### 1.2 Bresenhamův algoritmus

> **Jednovětá podstata:** Bresenham eliminuje floaty zavedením celočíselné rozhodovací proměnné `p`, která kumuluje chybu a rozhoduje, zda se vedlejší souřadnice zvýší o 1 — celý algoritmus pracuje pouze s `+`, `-` a posuvy.

**Platí pro k ∈ ⟨0, 1⟩, x1 < x2 (1. oktant) — ostatní symetrií.**

**Odvození rozhodovací proměnné:**

```
y_real = k(x_i + 1) + b
d1 = y_real - y_i          (vzdálenost k dolnímu pixelu)
d2 = (y_i + 1) - y_real    (vzdálenost k hornímu pixelu)

d = d1 - d2 = 2k(x_i+1) - 2y_i + 2b - 1

Vynásobíme Δx (aby zmizely floaty):
p_i = Δx · d = 2Δy·x_i - 2Δx·y_i + const
```

**Inkrementální update:**

```
p_{i+1} = p_i + 2Δy - 2Δx·(y_{i+1} - y_i)
```

**Větve:**

|Podmínka|yi+1|pi+1|
|---|---|---|
|`p_i < 0` (d1 < d2, blíže k dolnímu)|`y_i` (beze změny)|`p_i + 2Δy`|
|`p_i ≥ 0` (d1 ≥ d2, blíže k hornímu)|`y_i + 1`|`p_i + 2Δy - 2Δx`|

**Iniciální hodnota:** `p_0 = 2Δy - Δx` (ze `x_0 = y_0 = b = 0`)

**Kód (1. oktant):**

```c
init:
  c0 = 2*(y2 - y1)          // 2Δy
  c1 = c0 - 2*(x2 - x1)     // 2Δy - 2Δx
  p  = c0 - (x2 - x1)       // p0 = 2Δy - Δx

Bresenham(x1, y1, x2, y2):
  setPixel(x1, y1)
  for i = x1+1 to x2:
    if p < 0:  p += c0          // větev A
    else:      p += c1; y1++    // větev B
    setPixel(i, y1)
```

> ⚠️ **Záměna větví je nejčastější chyba na státnici.** A = `p < 0` → y se NEMĚNÍ. B = `p ≥ 0` → y se ZVYŠUJE.

## 2. Vyplňování oblastí

> **Co to je:** Algoritmy pro rasterizaci interiéru plošných útvarů definovaných buď geometricky (hranice jako polyline) nebo pixelově (hranice v obrazové paměti).

### 2.1 Scan-line polygon filling

> **Jednovětá podstata:** Scan-line filling prochází polygon řádek po řádku, pro každou scanline nalezne průsečíky s hranami polygonu, seřadí je podle x a vyplní mezilehlé úseky — aktivní seznam průsečíků zaručuje vždy sudý počet bodů.

**Předzpracování (jednou):**

1. Orientace hran: první bod nahoře, druhý dole
2. **Odstranění VŠECH horizontálních hran** (nezpůsobují průsečíky scanline)
3. **Systematické zkrácení hran o 1 v y (zespoda)** → řeší rohové body
4. Nalezení YMAX, YMIN

**Hlavní cyklus:**

```
for y = YMAX downto YMIN:
    najdi průsečíky scanline y s hranami  ← topologie
    seřaď průsečíky dle X                 ← bubble sort (skoro seřazený)
    vykresli horizontální úseky (liché–sudé páry)
```

**Datová struktura hrany (6 polí):**

|Pole|Typ|Mění se v cyklu?|
|---|---|---|
|`Y_upper`|int|Ne|
|`Y_lower`|int|Ne|
|`step_X`|float (Δx/Δy)|Ne|
|`X_upper`|float|Ano (akumulátor)|
|`intersection_X`|int|Ano (= round(X_upper))|
|`next`|ptr|Ne|

Active list má **vždy sudý počet uzlů** (každá scanline vstupuje do hrany a vystupuje z ní).

**Inverzní plnění (XOR):**

- Pro každou hranu: digitalizace po Δy=1 → XOR_LINE do X_max
- Výplň nepřekrývá dříve nakreslené objekty

**Stencil buffer:**

- Nekonvexní oblasti → jednobitový buffer (XOR výsledky)
- Konvexní oblasti → pole párů `[XL, XR]`

**Vlastnictví hrany (top-left rule):**

- **Levá a horní** hrana patří vyplněné oblasti → minimalizuje překreslování sousedních polygonů; nezávislé na pořadí

### 2.2 Juan Pineda — vyplňování trojúhelníku

> **Jednovětá podstata:** Metoda Juana Pinedy testuje příslušnost pixelu k trojúhelníku pomocí tří hranových funkcí E_i vyhodnocovaných inkrementálně — pixel je uvnitř, pokud jsou všechny tři E_i kladné, a celý algoritmus lze snadno paralelizovat na GPU.

    height="600px" 
    frameborder="0" 
    style="border-radius: 8px; border: 1px solid #444;">
</iframe>

**Hranová funkce** pro hranu A→B a testovaný bod P:

```
E(xP, yP) = (xB - xA)(yP - yA) - (yB - yA)(xP - xA)
```

- `E > 0` → P je **vlevo** od hrany (uvnitř pro CCW orientaci)
- `E = 0` → P leží přímo na hraně

**Algoritmus:**

1. Inicializace: vypočti `E_i(x0, y0)` pro všechny 3 hrany a levý horní roh bounding boxu
2. Procházení bounding boxu řádek po řádku:
    - Aktualizace `E_i` inkrementálně: posun o (+1,0) přičte `-(yB-yA)`, posun o (0,+1) přičte `(xB-xA)`
    - Pixel je **uvnitř** ↔ `E_0 > 0 ∧ E_1 > 0 ∧ E_2 > 0`

**Proč je GPU-friendly:** Každý pixel nezávislý → masivní paralelizace.

### 2.3 Seed-fill (rasterová oblast)

> **Jednovětá podstata:** Seed-fill algoritmy vyplňují uzavřenou oblast v obrazové paměti šířením z počátečního „seed" pixelu přes sousední nevyplněné pixely — rekurzivní varianta je neefektivní, scan-line seed-fill ji nahrazuje zásobníkem celých segmentů.

**Sousedství:**

- **4-spojité**: sousedé vlevo, vpravo, nahoru, dolů → nemusí vyplnit diagonálně spojenou oblast
- **8-spojité**: + 4 diagonální sousedy → může „vytéct" diagonálně tenkou hranicí

**Rekurzivní seed-fill:**

```
flood_fill(x, y):
  if pixel(x,y) == boundary or already_filled: return
  setPixel(x, y)
  flood_fill(x±1, y)
  flood_fill(x, y±1)
```

- Počet rekurzivních volání = počet vnitřních pixelů → **velmi neefektivní** (stack overflow)

**Scan-line seed-fill (efektivní):**

```
push(seed)
do:
  pop (X, Y)
  najdi levý a pravý okraj segmentu na řádku Y → vyplň celý segment
  pro každý volný segment na řádku Y+1 → push 1 seed
  pro každý volný segment na řádku Y-1 → push 1 seed
while !stack.empty()
```

- Zásobník obsahuje **celé segmenty**, ne jednotlivé pixely

## 3. Ořezávání (Clipping)

> **Co to je:** Odříznutí geometrických primitiv na hranici ořezávacího okna (viewport) — nezbytný krok renderovací pipeline před rasterizací.

### 3.1 Cohen-Sutherland — ořezávání úseček

> **Jednovětá podstata:** Cohen-Sutherland přiřadí každému koncovému bodu 4-bitový outcode kódující jeho polohu vůči 4 hranám okna a pomocí AND/OR testů rychle detekuje triviálně přijatelné a odmítnutelné úsečky, zbytek iterativně ořezává.

**Outcode podle konvence přednášky** (4 bity: L R T B — left, right, top, bottom):

```
bit 3 (L): x < xmin   → 1000
bit 2 (R): x > xmax   → 0100
bit 1 (T): y > ymax   → 0010
bit 0 (B): y < ymin   → 0001
```

Příklady: vlevo `1000`, nahoře `0010`, vlevo nahoře `1010`, vpravo dole `0101`, uvnitř `0000`.

**Testy:**

|Test|Výsledek|Akce|
|---|---|---|
|`OC(V1) OR OC(V2) == 0000`|Triviálně UVNITŘ|Kresli|
|`OC(V1) AND OC(V2) != 0000`|Triviálně VNĚ|Zahoď|
|Jinak|Průsečík s oknem|Ořízni jeden bod a opakuj|

**Ořezávání:** Vyber endpoint s nenulovým outcodem → najdi průsečík s příslušnou hranou → nahraď endpoint průsečíkem → opakuj testy.

> ⚠️ **Záměna AND/OR:** AND ≠ 0 → VNĚ (oba sdílí stejnou stranu). OR = 0 → UVNITŘ (oba bez bitu).

---

### 3.2 Liang-Barsky — parametrické ořezávání

> **Jednovětá podstata:** Liang-Barsky vyjádří úsečku parametricky jako `P(t) = P1 + t·ΔP` pro `t∈[0,1]` a každé ze 4 hranic okna přiřadí dvojici (p, q), kde `p<0` znamená vstup do okna a `p>0` výstup — iterací přes všechny 4 hranice aktualizuje interval `[t1, t2]` a ořeže úsečku v jediném průchodu.

    width="100%" 
    height="600px" 
    frameborder="0" 
    style="border-radius: 8px; border: 1px solid #444;">
</iframe>

**Parametrizace:**

```
x = x1 + t·Δx,  y = y1 + t·Δy,  t ∈ [0, 1]
```

**Čtyři hranice okna:**

|Hrana|p|q|
|---|---|---|
|Levá (x ≥ xmin)|`p1 = -Δx`|`q1 = x1 - xmin`|
|Pravá (x ≤ xmax)|`p2 = +Δx`|`q2 = xmax - x1`|
|Dolní (y ≥ ymin)|`p3 = -Δy`|`q3 = y1 - ymin`|
|Horní (y ≤ ymax)|`p4 = +Δy`|`q4 = ymax - y1`|

**Testovací logika** pro každou hranu `(p, q)`:

```
t = q / p
if p < 0:  vstup do okna → if t > t1: t1 = t  (if t > t2: ZAHOĎ)
if p > 0:  výstup z okna → if t < t2: t2 = t  (if t < t1: ZAHOĎ)
if p = 0:  rovnoběžně → if q < 0: ZAHOĎ (mimo okno)
```

**Finální test:** `if t1 > t2` → celá úsečka mimo okno.

**Výsledné ořezané body:**

- `if t1 > 0`: nový P1 = `(x1 + t1·Δx, y1 + t1·Δy)`
- `if t2 < 1`: nový P2 = `(x1 + t2·Δx, y1 + t2·Δy)`

> ⚠️ Liang-Barsky je efektivnější než Cohen-Sutherland: nepočítá průsečíky se všemi hranami, jen aktualizuje `t1/t2`.

### 3.3 Sutherland-Hodgman — ořezávání polygonů

> **Jednovětá podstata:** Sutherland-Hodgman zpracovává polygon jako reentrant pipeline — každá ořezávající hrana okna dostane celý seznam vrcholů, zpracuje ho a výsledný seznam předá dál — je omezen na konvexní ořezávací okno, u nekonvexních vstupních polygonů může generovat „fantomové hrany".

**Nemůže být nahrazeno ořezáváním čar** — polygon po ořezu mění počet vrcholů.

**4 případy pro hranu okna (IN = uvnitř, OUT = vně):**

|Předchozí|Aktuální|Výstup|
|---|---|---|
|IN|IN|B|
|IN|OUT|průsečík|
|OUT|OUT|nic|
|OUT|IN|průsečík + B|

**Algoritmus (reentrant pipeline):**

```
for každou ořezávající hranu okna:
    input_list ← output_list předchozí fáze
    output_list ← []
    for každý vrchol B v input_list:
        A ← předchozí vrchol
        dle kombinace (A,B) IN/OUT → přidej do output_list
```

**Omezení:**

- Ořezávací okno musí být **konvexní**
- Nekonvexní vstupní polygon → **fantomové hrany** (propojení bodů, kde by polygon neměl být) — vizuálně vadí jen u outline, ne u filled

---

### 3.4 Weiler-Atherton — obecné ořezávání polygonů

> **Jednovětá podstata:** Weiler-Atherton udržuje dva oddělené seznamy vrcholů (subject polygon a clip polygon), na každém průsečíku přepne aktivní seznam a takto procházením přes všechny průsečíky sestaví výsledné ořezané polygony — zvládá libovolné nekonvexní polygony i díry.

**Princip:**

1. Vytvoř propojený seznam vrcholů subject polygonu a clip polygonu
2. Označ průsečíky jako „vstupní" (subject → in) nebo „výstupní" (subject → out)
3. Procházej subject polygon: na **vstupním** průsečíku přepni na clip polygon (CW), na **výstupním** přepni zpět na subject polygon
4. Každá uzavřená smyčka = jeden výsledný polygon

**Výhoda oproti Sutherland-Hodgman:** Zvládá nekonvexní clip okno i nekonvexní subject polygon.

## ⚠️ Státnicové chytáky

**1. Bresenham — větve A/B:**

> Větev A (`p < 0`): y se **NEMĚNÍ**, `p += 2Δy`. Větev B (`p ≥ 0`): y++, `p += 2Δy - 2Δx`. Nejčastější záměna na státnici.

**2. Bresenham — proč vynásobení 2Δx:**

> `d = d1 - d2` obsahuje zlomek (racionální číslo). Vynásobením rovnice hodnotou `Δx` dostaneme čistě celočíselnou proměnnou `p_i = Δx · d` → eliminace jediného reálného čísla.

**3. Scan-line — proč ignorujeme horizontální hrany:**

> Odstraňují se **všechny** horizontální hrany (ne jen spodní!). Horizontální hrana by způsobila problémy s počítáním průsečíků — scanline s ní sdílí nekonečně mnoho bodů.

**4. Scan-line — rohový bod:**

> Bez oříznutí by vrchol sdílený dvěma hranami byl počítán dvakrát (sudý počet → nevyplněno), přičemž správně je jednou. Řešení: každá hrana se zkrátí o 1 pixel zespoda.

**5. Cohen-Sutherland — AND vs OR:**

> `AND != 0` → oba body sdílejí alespoň jednu stejnou vnější polorovinu (např. oba vlevo) → zahoď. `OR == 0` → oba body nemají žádný příznak → jsou uvnitř. Záměna způsobí nesprávné zahazování/kreslení.

**6. Liang-Barsky — t1 > t2:**

> Pokud po zpracování všech 4 hranic platí `t1 > t2`, celá úsečka leží mimo okno a nic se nekreslí.

**7. Sutherland-Hodgman — proč nefunguje pro nekonvexní okno:**

> Reentrant pipeline zpracovává každou hranu nezávisle jako polorovinu. U nekonvexního okna nelze okno rozložit na poloroviny tak, aby průnik dal správný výsledek. Výsledek obsahuje „fantomové hrany" propojující body, kde polygon opustil a znovu vstoupil do nekonvexní oblasti.

**8. Seed-fill — 4 vs 8-spojité:**

> 4-spojité nemusí vyplnit oblast spojenou jen diagonálně. 8-spojité může „vytéct" přes diagonálně tenkou hranici (jeden pixel hranice). Volba závisí na topologii oblasti a hranice.
