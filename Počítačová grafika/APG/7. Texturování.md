## High-level přehled

Textura je levný podvod — místo modelování mikrostruktury povrchu geometrií (letokruhy, póry, spáry) uložíš data do obrazu a při renderování se "podíváš" do správného místa. Celý mechanismus stojí na **inverzním mapování**: pro každý pixel obrazovky najdeš bod povrchu → z něj UV souřadnice → z UV barvu (nebo normálu, výšku, průhlednost...). Přímé mapování (textura → obrazovka) nefunguje — nevíš, které pixely daný texel pokrývá.

Textura nemusí modulovat jen barvu — moduluje normály (bump/normal map), geometrii (displacement), průhlednost (alpha), příchozí světlo (environment map). MIP mapping řeší fundamentální problém minifikace: jeden pixel obrazovky odpovídá mnoha texelům → předpočítej pyramidu rozlišení, vyber správnou úroveň.

## 1. Principy texture mapping

### Inverzní mapování

```
T: [u,v] → Color          (textura: UV souřadnice → hodnota)
M: [x,y,z] → [u,v]        (mapování: bod povrchu → UV)
T∘M: [x,y,z] → [u,v] → Color
```

> Ve slajdech je kompozice značena `M∘T`, ale při běžné matematické konvenci „pravá funkce se aplikuje první" je správné pořadí `T∘M`: nejdřív bod převedeme pomocí `M` na UV a potom funkcí `T` získáme hodnotu textury.

Pro jednoduché tvary existuje analytický předpis M:

```
Válec: u = atan2(y,x)/(2π),  v = z/výška
Koule: u = atan2(y,x)/(2π),  v = asin(z/r)/π + 0.5
```

![[inversetexturemapping.png]]

### Proxy mapování (pro složité tvary)

Konceptuální konstrukce v přednášce probíhá dopředně:

1. **Krok 1:** Textura → proxy (analytické mapování na kouli/válec/krychli)
2. **Krok 2:** Proxy → skutečný objekt.

Při rasterizaci se ale používá **inverzní lookup**: bod objektu → odpovídající bod proxy → UV → hodnota textury. Vazbu objekt → proxy lze určit čtyřmi způsoby:
    - Odražený paprsek
    - Objektová povrchová normála
    - Centroid objektu
    - Proxy povrchová normála

### Environment mapping

Levná alternativa ray tracingu pro odrazy okolí na povrchu objektu.

```
r = reflect(viewDir, normal)
color = environmentMap.sample(r)
```

**Dvě fáze:**

1. Vytvoření mapy prostředí (render z pozice objektu, nebo speciální kamera)
2. Lookup podle odraženého směru při renderingu

![[environmentalmapping.png]]

**Formáty:**

|Formát|Popis|Nevýhoda|
|---|---|---|
|Sphere map|Jedna textura, kulová projekce|Singularita u okrajů, pohledově závislá|
|Cubemap|6 textur (stěny krychle)|— nejpoužívanější, HW podpora|
|Duální paraboloid|2 textury (přední + zadní polokoule)|Heidrich & Seidel 1998|

Omezení: předpokládá prostředí **nekonečně daleko** — nefunguje pro blízké reflektory.

**HDR environment mapy (Light probes)** — Paul Debevec, image-based lighting.

### Perspektivně korektní mapování

Lineární interpolace UV ve screen space je nekorektní pro perspektivní projekci — textura se "kroutí".

**Řešení:** Interpolovat podělené perspektivní složkou `w`:

```
Pro každý vrchol:
  u' = u/w,  v' = v/w,  w' = 1/w

Lineárně (barycentricky) interpoluj u', v', w' přes trojúhelník.

Pro každý fragment:
  u = u'/w',  v = v'/w'
```

V **ray tracingu** problém nevzniká — UV se získávají přímo z barycentrických souřadnic průsečíku paprsku.

### Rozšíření textury (wrapping)

```
Repeat:   uv = fract(uv)         → dlaždice
Mirror:   opakování se střídá    → hladší přechody na švech
Clamp:    uv = clamp(uv, 0, 1)   → krajní texel se natáhne
Border:   mimo [0,1] → pevná barva
```

## 2. UV mapy

### UV parametrizace sítě (unwrap)

Algoritmické rozvinutí 3D povrchu do 2D roviny `[0,1]²`. Každému vrcholu sítě přiřadíš souřadnice `(u,v)`.

**Dva základní problémy:**

**1. Area-preserving vs. conformal mapping** — nelze současně zachovat obojí:

- **Area-preserving:** zachovává plochu, deformuje úhly (tvar)
- **Conformal:** zachovává úhly (tvar), plochy se zkreslují

**2. Diskontinuity (švy):**

- 3D povrch (koule) nejde rozvinout do 2D bez řezů
- Na švech nutná **duplikace vrcholů** — jeden fyzický vrchol leží na hraně řezu, v UV prostoru potřebuješ dvě různé souřadnice
- Švy minimalizovat a umísťovat do méně viditelných oblastí

**Texturovací atlas** = více objektů (nebo částí jednoho objektu) napakovaných do jediné textury. Snižuje počet draw callů, efektivní využití paměti.

## 3. Typy textur

### Přehled modulací

|Typ textury|Co moduluje|Vstup|
|---|---|---|
|Diffuse/Albedo|Barvu (diffuse složku)|RGB obraz|
|Spekulární mapa|Intenzitu lesku per-pixel|Greyscale/RGB|
|Bump map|Normály (via derivace)|Šedotónový obraz (výška)|
|Normal map|Normály (přímo)|RGB (zakódovaný směr)|
|Displacement map|Skutečnou geometrii|Greyscale (výška)|
|Alpha mask|Průhlednost|Greyscale/Alpha kanál|
|Environment map|Příchozí světlo (odrazy)|Cube/sphere textura|

### Bump map

- Vstup: šedotónový obraz = výšková funkce `F(u,v)`
- Z výšky se **derivací** spočítají perturbace normály

**Matematika (Blinn 1978):**

```
Tečné vektory k virtuálnímu povrchu:
  p'_u = p_u + F_u · n
  p'_v = p_v + F_v · n

Nová normála:
  n' = p'_u × p'_v = n + d

  d = F_u(n × p_u) - F_v(n × p_v)
```

`F_u`, `F_v` = parciální derivace výškové mapy (v praxi: rozdíl sousedních texelů = detekce hran).

Omezení: silně zvrásněný povrch by stínil sám sebe — technika to nedokáže simulovat.

### Normal map

- RGB přímo kóduje směr normály: `(R,G,B) → (x,y,z)`
- Typicky v **tangent space** (modrá barva = normála rovná nahoru `(0,0,1)`)
- Před osvětlením se normála převede z tangent space do prostoru výpočtu pomocí TBN báze `(tangent, bitangent, normal)`
- Bez nutnosti derivace za běhu a může přímo zakódovat obecný lokální směr normály
- **Neovlivňuje siluetu** — geometrie se fyzicky nemění

### Displacement map

- Posouvá **skutečné vrcholy** geometrie
- **Viditelné na siluetě** objektu
- Drahé — potřeba dostatečná tessellace meshe

### Alpha mask

```
Alpha = 1.0  → pixel plně viditelný
Alpha = 0.0  → pixel zahozen (discard)
Alpha = 0.5  → poloprůhledný (blending)
```

Cut-out rendering: obdélníková geometrie, ale alpha "vyřízne" tvar (tráva, listí, plot). Fragment shader zavolá `discard` pro `alpha = 0`.

### Parallax mapping

Rozšíření normal mapy — posune UV souřadnice podle výšky a směru pohledu, aby povrch vypadal skutečně hluboký:

```glsl
vec2 ParallaxMapping(vec2 texCoords, vec3 viewDir) {
    float height = texture(depthMap, texCoords).r;
    vec2 p = viewDir.xy / viewDir.z * (height * height_scale);
    return texCoords - p;
}
```

**Parallax occlusion mapping** = vícekrokové hledání průsečíků podél pohledového paprsku → věrohodné vlastní stínování a překrytí.

## 4. MIP mapping

### Problém minifikace

Objekt daleko → jeden pixel obrazovky odpovídá mnoha texelům (např. 50×50). Vzít jeden texel ze středu = aliasing, blikání, moiré vzory.

### Řešení: předpočítaná pyramida

**MIP** = _multum in parvo_ (lat. mnoho v malém)

```
Úroveň 0:  512×512  (originál)
Úroveň 1:  256×256  (průměr 2×2 bloků)
Úroveň 2:  128×128
  ...
Úroveň 9:    1×1    (průměr celé textury)
```

**Paměťový overhead: +33 %** Geometrická řada: `1/4 + 1/16 + ... = 1/3` → celkem 4/3 původní velikosti.

### Výběr úrovně `d`

Podle rychlosti změny UV souřadnic přes sousední pixely (screen-space derivace):

```glsl
vec2 dx = dFdx(uv * textureSize);
vec2 dy = dFdy(uv * textureSize);
float d = 0.5 * log2(max(dot(dx, dx), dot(dy, dy)));
```

`textureSize` je rozlišení základní úrovně v texelech. Velký gradient UV → textura se rychle mění → vyber nižší rozlišení (vyšší úroveň pyramidy).

### Trilineární interpolace

1. **Bilineární interpolace** uvnitř úrovně `floor(d)` → hodnota A
2. **Bilineární interpolace** uvnitř úrovně `ceil(d)` → hodnota B
3. **Lineární interpolace** mezi A a B podle frakční části `d`

### Nevýhoda MIP mappingu

Rozmazání obrazu (blurring) ve velkých vzdálenostech. Příčina: MIP mapa bere **čtvercové** vzorky, ale při šikmém pohledu je footprint pixelu v UV prostoru **elipsa** → přebytečné rozmazání.

Řešení: **Anizotropický filtr** (AF) — obdélníkové vzorky podél směru pohledu. Standardní GPU feature (2×/4×/8×/16× AF).

## 5. Filtrování textur — přehled

### Magnifikace (objekt blízko)

Jeden texel → mnoho pixelů. Textura vypadá "rozpixelovaná".

|Metoda|Kvalita|Cena|
|---|---|---|
|Nearest neighbor|Pixelovaný look|O(1)|
|Bilineární interpolace|Hladké|4 vzorky|
|Bikubická (Hermite)|Nejhladší|16 vzorků|

### Minifikace (objekt daleko)

Mnoho texelů → jeden pixel. Aliasing.

|Metoda|Kvalita|Paměť|
|---|---|---|
|Nearest neighbor|Aliasing|—|
|MIP mapping|Dobré, rozmazává šikmo|+33 %|
|Summed area table|Přesný průměr osově zarovnaného obdélníku|+300 % (32bit)|

### Summed area table

2D prefixový součet: `SAT[x,y]` = součet všech texelů v obdélníku `(0,0)→(x,y)`.

Průměr obdélníku `(x1,y1)→(x2,y2)` v O(1) — inclusion-exclusion:

```
součet = SAT[x2,y2] - SAT[x1-1,y2] - SAT[x2,y1-1] + SAT[x1-1,y1-1]
průměr = součet / plocha
```

Nevýhoda: hodnoty jsou součty (ne bajty) → 32bit int → 4× větší paměť.

## ⚠️ Státnicové chytáky

- **Bump mapa ≠ přímý zápis normál.** Bump mapa je výšková mapa (šedotón) — normály se z ní teprve derivují za běhu. Normal mapa má normály přímo v RGB. Záměna je nejčastější chyba.
- **Silueta:** Normal mapa a bump mapa **neovlivňují siluetu** — geometrie se fyzicky nemění. Displacement mapa ano — posouvá vrcholy. U státnice skoro jistá otázka.
- **Proxy mapování — dva pohledy:** Konstrukce je textura → proxy → objekt, ale implementační lookup při rasterizaci běží inverzně objekt → proxy → UV → textura.
- **Perspektivně korektní interpolace:** Klíč je dělit `w` — interpolovat `u/w`, `v/w`, `1/w`. V ray tracingu problém nevzniká — UV z barycentrických souřadnic průsečíku, žádná screen-space interpolace.
- **MIP overhead = 33 %**, ne 50 % ani 100 %. Geometrická řada 1/4 + 1/16 + ... = 1/3.
- **Trilineární interpolace** = bilineární ve dvou sousedních úrovních MIP + lineární interpolace mezi nimi podle frakční části `d`. Bez ní jsou viditelné skoky mezi úrovněmi.
- **SAT = 2D prefixový součet**, ne indexování regionů. `SAT[x,y]` = součet všech texelů v obdélníku `(0,0)→(x,y)`. Paměť: 4× větší než originál.
- **Environment mapping předpokládá prostředí nekonečně daleko** — pro blízké objekty nefunguje správně.
- **Cubemap výhoda oproti sphere mapě:** rovnoměrné pokrytí bez singularit, HW podpora, snadná real-time aktualizace.
