## 1. B-rep (Hraniční reprezentace)

Popisuje **povrch** objektu, ne jeho objem. Nejběžnější forma: trojúhelníková síť.

|Vlastnost|Hodnota|
|---|---|
|GPU rendering|✅ snadné|
|Booleovské operace|❌ složité|
|Info o vnitřku objektu|❌ žádná|
|Test „bod uvnitř"|❌ netriviální (ray casting)|

---

### 1.1 Polygonální síť (Mesh)

#### Jak uložit trojúhelníky v paměti

|Reprezentace|Jak funguje|Nevýhoda|
|---|---|---|
|**Triangle soup**|3 explicitní vrcholy × každý trojúhelník|duplikovaná data|
|**Indexed mesh**|pole vrcholů + pole indexů (3× int → 1 trojúhelník)|standard v praxi|
|**Triangle strip**|každý nový vrchol + předchozí 2 = nový trojúhelník|složitější sestavení|
|**Triangle fan**|pivot V0 sdílený všemi, + 2 sousední vrcholy|jen pro vějíře/kruhy|

**Vzorce:**

- Strip: `n` vrcholů → `n − 2` trojúhelníků
- Fan: `n` vrcholů (+ pivot) → `n − 1` trojúhelníků

#### Data vrcholu

- **Pozice** `(x, y, z)`
- **Normála** — pro Phong shading
- **Tangenta / Bitangenta** — pro normal mapping: `[Δp1, Δp2] = [Δu1, Δu2] · [T, B]`
- **UV souřadnice** — texturování
- **Skinning** — joint ID + váhy (animace)

#### Pořadí vrcholů — orientace stěny

```
CCW (counter-clockwise) = přední stěna (front face)  →  normála míří ven
CW  (clockwise)         = zadní stěna  (back face)   →  GPU zahodí (back-face culling)
```

Normála stěny: `n = (V1 − V0) × (V2 − V0)`

#### Typy stěn

- **Planární vs parametrické** (Bezier, NURBS)
- **Jednostranné vs oboustranné** (oboustranné = culling vypnutý, látky, listy)
- **Stěny s dírami** — 1 vnější hranice + N vnitřních, propojené pomocnými hranami

#### Typy hran

|Typ|Popis|
|---|---|
|**Ostré (sharp)**|reálné hrany geometrie|
|**Vnitřní (auxiliary)**|pomocné pro triangulaci|
|**Siluetové**|dynamicky při renderingu (obrys z pohledu kamery)|

### 1.2 Winged-Edge (Okřídlená hrana)

#### Proč ji potřebujeme

Indexovaný mesh neumí odpovědět na: „Které stěny sousedí s touto hranou?" ani „Jaké hrany vycházejí z tohoto vrcholu?" — musíš prohledat celé pole. Winged-edge tyto dotazy řeší v **O(1)**.

#### Tři tabulky

|Tabulka|Co ukládá|
|---|---|
|**Vrchol → hrana**|Každý vrchol zná 1 svou incidentní hranu|
|**Stěna → hrana**|Každá stěna zná 1 svou reprezentativní hranu|
|**Hrana → hrana**|Klíčový element — viz níže|

#### Záznam okřídlené hrany (8 ukazatelů)

```
hrana e:
  vs         = V_start         (počáteční vrchol)
  ve         = V_end           (koncový vrchol)
  fl         = F_left          (stěna vlevo od směru vs→ve)
  fr         = F_right         (stěna vpravo od směru vs→ve)
  prev_left  = hrana přicházející do V_start po levé stěně
  next_left  = hrana odcházející z V_end po levé stěně
  prev_right = hrana přicházející do V_end po pravé stěně
  next_right = hrana odcházející z V_start po pravé stěně
```

> **"Křídla"** = čtyři sousední hrany (`prev/next` vlevo i vpravo) — odtud název.

#### Traversal stěny F

```
hrana = F.reprezentativni_hrana
opakuj:
    hrana = hrana.next_left
dokud hrana != startovní hrana
```

#### Traversal vrcholu V

```
hrana = V.incidentni_hrana
opakuj:
    hrana = hrana.prev_right
dokud hrana != startovní hrana
```

#### Příklad: kvádr

- 8 vrcholů, 12 hran, 6 stěn
- Tabulka hrana→hrana: **12 řádků**, každý s 8 pointery

---

### 1.3 Manifoldy

**2-manifold** = pro každý bod na povrchu existuje okolí ekvivalentní disku → povrch jde „rozvinout" do roviny.

#### Kdy winged-edge selhává (non-manifold)

|Případ|Proč se rozbije|
|---|---|
|**3+ stěny na 1 hraně**|`fl` a `fr` jsou jen 2 políčka — třetí stěnu nelze uložit|
|**Bowtie vrchol**|Dva trojúhelníky sdílí jen bod, ne hranu — okolí není disk|

#### Řešení: Winged half-edge (DCEL)

Místo jedné hrany se dvěma stěnami → **dvě half-edges**, každá patří jedné stěně a má vlastní `next/prev`. Zvládne non-manifoldy.

#### Euler–Poincaré vzorec

```
V − E + F − R = 2(S − H)
```

|Symbol|Význam|
|---|---|
|V|počet vrcholů|
|E|počet hran|
|F|počet stěn|
|R|díry ve stěnách (rings)|
|S|oddělené shelly|
|H|průchozí díry (tunnels)|

**Příklady:**

- Kvádr: `8 − 12 + 6 − 0 = 2(1 − 0) = 2` ✓
- Torus (donut): `V − E + F = 0`, protože `H=1` → `2(1−1) = 0`

---

### 1.4 Mesh Graph

- Zobecnění indexované sítě — **orientovaný acyklický graf (DAG)**
- Jen **vrcholy** nesou geometrická data (pozice, normála…)
- Hrany grafu = topologické vazby (ne geometrické hrany meshe)
- Umožňuje hierarchickou reprezentaci, LOD, instancing

---

### 1.5 Hladké povrchy

#### Parametrické povrchy

- Analyticky přesné: koule, elipsoid, válec
- Po částech: **Bezier patche**, **NURBS** (kubické polynomy)
- Vždy se triangulují před GPU renderováním

#### Dělící povrchy (Subdivision)

Hrubá mesh (control cage) → opakované dělení + přesun vrcholů → hladký povrch

|Schéma|Pracuje s|Poznámka|
|---|---|---|
|**Loop**|trojúhelníky||
|**Catmull-Clark**|quady|Pixar, Maya, Blender|
|**Doo-Sabin**|quady||

**HW podpora:** hull shader (control cage) + tessellation shader (dělení na GPU za běhu)

---

### 1.6 Výšková pole (Height Fields)

- Uniformní 2D mřížka + výška `h(x, y)` v každém bodě
- Každá buňka → 2 trojúhelníky pro rendering
- **Omezení:** pouze 2.5D — nelze reprezentovat převisy (jeskyně, oblouky)
- Použití: terény, displacement mapy, oceány

---

### 1.7 Billboardy / Sprity / Impostors

|Typ|Popis|
|---|---|
|**Sprite**|2D obrázek místo 3D geometrie|
|**Billboard**|sprite automaticky orientovaný ke kameře|
|**Impostor**|billboard s hloubkovou informací|

- **Výhoda:** 1 quad místo tisíců trojúhelníků
- **Použití:** tráva, listí, vzdálené stromy, částice, efekty

## 2. Volumetrická reprezentace

### 2.1 Voxely

- **Voxel** = volume element, 3D ekvivalent pixelu
- Prostor rozdělen na **uniformní mřížku krychlí**
- Každá buňka nese hodnotu: boolean (plná/prázdná), hustota, teplota, barva+alpha...

**Paměťová náročnost:**

```
100×100×100    = 1 milion voxelů   → relativně malá sada
1000×1000×1000 = 1 miliarda voxelů → 4 GB (při 4B/voxel)
```

**Výhody:**

- Test „bod uvnitř" triviální — zkontroluj hodnotu buňky
- Přirozené pro CT/MRI data, simulace, volumetrický rendering

**Nevýhody:**

- Obrovská paměťová náročnost
- Redundance — prázdné buňky ukládány zbytečně

**Prostorové řazení (spatial ordering):**

- Lineární pořadí buněk v paměti ovlivňuje cache coherence
- Lepší než row-major: **Peano-Hilbertova křivka**, spirálové řazení
- Cíl: sousední voxely v prostoru → blízko i v paměti

---

### 2.2 Oktalový strom (Octree)

Hierarchická komprese voxelové reprezentace.

**Princip rekurzivního dělení:**

1. Vezmi bounding box celé scény → **kořen**
2. Uzel **zcela prázdný** → list, neukládej potomky
3. Uzel **zcela plný** → list, označ jako plný
4. Uzel **smíšený** (obsahuje hranici) → **rozděl na 8 dětí**, opakuj

Každý vnitřní uzel má přesně **8 potomků** (proto „okta"). Analogie ve 2D: **quadtree** (4 potomci).

**Typy uzlů v octree:**

- Plný list → celá buňka je součástí objektu
- Prázdný list → celá buňka je prázdná
- Vnitřní uzel → smíšená buňka, má 8 potomků

**Výhody oproti uniformní mřížce:**

- Jemné dělení jen tam, kde je geometrie
- Prázdný prostor komprimovaný do jednoho uzlu — velká úspora paměti

**Složitost operací přes octree** (OR, MINUS, AND):

```
O(N_A · log N_B)
```

Pro každý list stromu A se prochází stromem B.

---

### 2.3 Zobrazení volumetrických dat (CT/MRI)

**Nepřímý rendering:**

- Z voxelů se nejdřív extrahuje geometrie → pak renderuješ na GPU
- Klíčový algoritmus: **Marching Cubes** — prochází mřížku krychlí a extrahuje **izoplochu**
- **Izoplocha** = množina bodů, kde data dosahují přesně zvolené **izohodnoty** (prahu)
- Např. pro kosti: izohodnota = hustota kosti → Marching Cubes vytvoří mesh povrchu kostí

**Přímý rendering (ray casting):**

- Paprsek prochází přímo voxelovou mřížkou, bez mezilehlé geometrie
- Každý vzorek mapován na barvu + průhlednost přes **transfer funkci**
- Flexibilnější (poloprůhlednost, vnitřní struktury), ale výpočetně náročnější

## 3. Graf scény (Scene Graph)

### 3.1 Datová struktura

Graf scény je **DAG** (Directed Acyclic Graph — orientovaný acyklický graf).

**Proč DAG a ne strom?** Jeden geometrický uzel (list) může mít **více rodičů** — více instancí na různých místech scény. To je **instancing**. Hrany reprezentují hierarchický vztah „je potomkem".

### 3.2 Typy uzlů (shora dolů)

```
Kořen (Root)
  └── Skupinové uzly (Group)              — logická organizace, pojmenování,
        └── Transformační uzly (Transform)        aktivace/deaktivace větve
              └── Stavové uzly (Material/Light)   — materiál, textura, světlo
                    └── Geometrické listy (Shape) — mesh, point cloud...
                                                    sdílené přes DAG
```

- **Kořen** — jediný vstupní bod, reprezentuje celou scénu.
- **Skupinové uzly** — čistě organizační, žádná geometrie ani transformace. Deaktivace skupiny = skrytí celé větve.
- **Transformační uzly** — nesou lokální matici (translate, rotate, scale). Výsledná world-space transformace listu = **součin matic na cestě od kořene** → renderer udržuje zásobník matic.
- **Stavové uzly** — materiál, textura, světlo, kamera. Platí pro celý podstrom pod nimi.
- **Geometrické listy** — jediné uzly bez potomků, nesou skutečná data (mesh). Na jeden list může ukazovat více transformačních uzlů → DAG.

> ⚠ Pozor na záměnu: skupinový uzel zastřešuje skupinu (např. „Les"). Geometrický list je sdílená geometrie (např. „Strom_mesh") — to je ten uzel s více rodiči.

### 3.3 Instancing — příklad: les s 10 000 stromy

```
Scéna (kořen)
  └── Les (skupinový uzel)
        ├── T₁ (transformace: pozice stromu 1) ──┐
        ├── T₂ (transformace: pozice stromu 2) ──┼──→ Strom_mesh (geometrický list)
        └── T₃ (transformace: pozice stromu 3) ──┘

Uloženo: 10 000 transformací + 1× geometrie stromu
```

**Výhody instancingu:**

- Geometrie v paměti pouze jednou
- Změna modelu stromu se projeví ve všech instancích najednou

**Implikace pro renderer:**

- Při průchodu DAGem udržovat zásobník transformačních matic
- Jeden uzel může být navštíven vícekrát → renderer musí ošetřit (značkování uzlů)

## 4. CSG — Constructive Solid Geometry

### 4.1 Struktura CSG stromu

```
Kořen = výsledný model (jeden objekt)
  ├── vnitřní uzly = booleovské operace nebo transformace
  └── listy = geometrická primitiva (implicitní forma)
```

**Listy** = primitiva definovaná implicitní rovnicí:

- Koule: `x² + y² + z² − r² ≤ 0`
- Kvádr, válec, kužel, ...
- Bod je **uvnitř** primitiva pokud `f(x,y,z) ≤ 0`

**Vnitřní uzly** = operace (pouze tři — pozor na záměnu s ADD):

- **OR (∪)** — sjednocení
- **MINUS (−)** — odečtení (A bez průniku s B)
- **AND (∩)** — průnik
- **Transformace** — translate, rotate, scale

### 4.2 Příklad: šroub

```
OR
├── MINUS                          ← tělo šroubu
│     ├── Válec (tělo)
│     └── Válec menší (díra)
└── MINUS / AND                    ← šestihranná hlavička
      ├── Kvádr
      └── ... (ořezy rohů dalšími kvádry)
```

Šestihranný hranol = AND několika hranolů/rovin, nebo MINUS rohů z kvádru.

### 4.3 Vlastnosti

**Jednoduchý test „bod uvnitř":** Vyhodnoť výraz od listů ke kořeni. U listu: `f(x,y,z) ≤ 0`? Operace kombinují booleovské výsledky.

**Modelování připomíná výrobu:** Vrtání = MINUS válec, frézování = MINUS kvádr. → Populární v průmyslovém CAD a **3D tisku**.

**Paměťově kompaktní** — ukládáš jen parametry primitiv a strom operací.

**Složitější renderování** — nemáš mesh pro GPU. Možnosti:

1. Ray casting — paprsek testuje každý uzel stromu
2. Konverze do B-Rep — nutná pro real-time rendering

## 5. Implicitní plochy

### 5.1 Definice

Implicitní plocha = množina bodů splňující:

```
f(x, y, z) = 0
```

Bod v prostoru:

- `f(x,y,z) < 0` → **uvnitř** objektu
- `f(x,y,z) = 0` → **na povrchu**
- `f(x,y,z) > 0` → **vně** objektu

### 5.2 Příklady primitiv

```
Koule (střed v počátku, poloměr r):
  f(x,y,z) = x² + y² + z² − r² = 0

Koule (střed v bodě c = (cx, cy, cz)):
  f(x,y,z) = (x−cx)² + (y−cy)² + (z−cz)² − r² = 0

Rovina (z = 0):
  f(x,y,z) = z = 0
```

> Tato primitiva jsou **listy CSG stromu** — proto CSG a implicitní plochy jdou ruku v ruce.

### 5.3 Metaballs (blob objekty)

Modelování měkkých, organických tvarů, které se přirozeně **slévají**.

**Princip:**

- Každý metaball = zdroj **potenciálového pole**, hodnota klesá se vzdáleností
- Povrch = **ekvipotenciální plocha** — množina bodů se stejnou celkovou hodnotou pole

**Vzorec:**

```
F(x,y,z) = Σᵢ Bᵢ · e^(−Aᵢ · rᵢ²) = T

kde:
  rᵢ = |p − pᵢ| / Rᵢ     (normalizovaná vzdálenost od středu pᵢ)
  T   = threshold (prahová hodnota) — pevná konstanta, nemění se!
  Aᵢ  = konstanta ovlivňující strmost pole
  Bᵢ  = konstanta ovlivňující sílu pole
  Rᵢ  = vzdálenost kde příspěvek klesne k 0
```

**Proč se metabally slévají:**

- T je pevný práh — nemění se
- Parametry Aᵢ, Bᵢ, Rᵢ se také nemění
- Když přiblížíš dva metabally, mění se **vzdálenost rᵢ** mezi nimi
- V prostoru mezi nimi začnou jejich pole vzájemně přispívat → součet F roste
- Jakmile F překročí T i mezi nimi, izoplocha se spojí do jednoho tvaru

**Chování:**

- Metabally daleko od sebe → **oddělené** povrchy
- Metabally blízko sebe → povrchy se **slévají** do jednoho tvaru

### 5.4 Vlastnosti implicitních ploch

**Výhody:**

- Triviální test „bod uvnitř" — vyhodnoť `f(x,y,z)` a porovnej s 0
- Automaticky hladký, spojitý povrch
- Přirozené slévání tvarů — ideální pro organické objekty, vodu, oheň
- Kompaktní — jen vzorec, žádná mesh

**Nevýhody:**

- Nelze přímo poslat na GPU
- Renderování: ray casting, nebo konverze na mesh (**Marching Cubes**)
- Obtížnější přesná kontrola tvaru (nemáš handle na každý vrchol)

### 5.5 Vztah k ostatním reprezentacím

```
Implicitní plochy
  ├── jsou listy CSG stromu
  ├── metaballs → organické modelování
  ├── diskretizací → voxely
  └── pro rendering → konverze přes Marching Cubes → B-rep
```

## 6. Graf scény vs. CSG strom — klíčový rozdíl

||Graf scény|CSG strom|
|---|---|---|
|Co je výsledkem|celá scéna|jeden objekt|
|Co jsou uzly|transformace, skupiny, listy|booleovské operace, transformace|
|Co jsou listy|geometrie (mesh)|geometrická primitiva (implicitní)|
|Struktura|DAG (instancing)|strom|
|Účel uzlů|umístění a organizace geometrie|matematická kombinace geometrie|

**Stručně:** CSG definuje _jak je objekt tvarově složen_. Graf scény definuje _jak jsou objekty umístěny a organizovány ve scéně_. CSG operuje na geometrii (OR, MINUS, AND), graf scény geometrii jen umísťuje a sdílí.
