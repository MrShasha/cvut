# Základní pojmy a značení rozvrhování

## Grahamova notace

Rozvrhovací úloha se zapisuje jako:

$$\alpha|\beta|\gamma$$

- $\alpha$ popisuje zdroje,
- $\beta$ popisuje omezení úloh,
- $\gamma$ je optimalizační kritérium.

Příklady:

| Zápis | Význam | Typické řešení |
| --- | --- | --- |
| `1 \|\| Cmax` | jeden zdroj, bez omezení, minimalizace konce dávky | libovolné pořadí |
| `1 \| rj, edj \| Cmax` | jeden zdroj, release times + hard deadlines | Bratleyho B&B |
| `1 \|\| ΣCj` | jeden zdroj, minimalizace součtu dokončení | SPT |
| `1 \|\| ΣwjCj` | jeden zdroj, vážený součet dokončení | WSPT |
| `1 \|\| Lmax` | jeden zdroj, max. lateness | EDD |
| `1 \| pmtn,rj \| Lmax` | preempce + release times | Hornův algoritmus |
| `P \| pmtn \| Cmax` | identické paralelní zdroje, preempce | McNaughton |
| `P \|\| Cmax` | paralelní zdroje bez preempce | LPT / DP / ILP |
| `P \| prec \| Cmax` | paralelní zdroje + precedence | List Scheduling |

## Symboly

| Symbol | Význam |
| --- | --- |
| $r_j$ | release time: úloha může začít nejdříve v čase $r_j$ |
| $p_j$ | processing time: doba zpracování |
| $d_j$ | due date: měkký termín, překročení se penalizuje |
| $\text{ed}_j$ | hard deadline: musí být splněn, jinak je rozvrh nepřípustný |
| $s_j$ | start time |
| $C_j=s_j+p_j$ | completion time |
| $F_j=C_j-r_j$ | flow time |
| $L_j=C_j-d_j$ | lateness, může být záporná |
| $T_j=\max(C_j-d_j,0)$ | tardiness, penalizuje jen zpoždění |

Due date je přání nebo penalizace. Hard deadline je tvrdá podmínka přípustnosti.

# Minimalizace $C_{\max}$

$C_{\max}$ je čas dokončení poslední úlohy.

## Jednoduché případy

**`1 || Cmax`:** všechny úlohy běží sekvenčně, proto:

$$C_{\max}=\sum_j p_j$$

Pořadí nehraje roli.

**`1 | rj | Cmax`:** procesor nikdy nemůže spustit úlohu před jejím $r_j$. V nejjednodušším modelu zpracováváme dostupné úlohy a případně čekáme na další release time.

**`1 | edj | Cmax`:** hard deadlines řeší EDF: nejbližší deadline první. Pokud EDF nestihne některý hard deadline, přípustný rozvrh neexistuje.

## NP-těžký případ: `1 | rj, edj | Cmax`

Každá úloha má časové okno:

$$r_j \le s_j,\qquad C_j\le \text{ed}_j$$

Samotné release times jsou jednoduché. Samotné deadlines jsou jednoduché. Jejich kombinace vytváří problém vkládání intervalů do pevných oken, což je NP-těžké.

NP-těžkost se dokazuje redukcí z 3-Partition: mezi pevné "zarážkové" úlohy vzniknou mezery velikosti $B$ a datové úlohy se do nich musí rozdělit po trojicích. Pokud to jde, rozvrh dosáhne cílového $C_{\max}$; pokud ne, některá úloha přeteče za poslední mezeru.

# Bratleyho algoritmus

Bratleyho algoritmus je Branch & Bound pro:

$$1|r_j,\text{ed}_j|C_{\max}$$

Prohledává permutace úloh, ale ořezává větve, které už nemohou vést k přípustnému nebo lepšímu rozvrhu.

## Větvení

Uzel stromu = prefix rozvrhu. V dalším kroku zvolíme, která dosud nezaplánovaná úloha přijde na další místo. List stromu = kompletní pořadí.

## Tři ořezávací principy

**1. Porušení deadline**

![[Assets/KO/Bratley-1.png]]

Pokud některá úloha v rozpracovaném rozvrhu končí po svém $\text{ed}_j$, větev je nepřípustná. Pokud je jasné, že problémová úloha už nemůže být v daném prefixu umístěna včas, lze ořezat i sourozenecké větve.

**2. Dekompozice při idle gap**

![[Assets/KO/Bratley-3.png]]

Pokud po prefixu procesor nutně čeká na všechny zbývající úlohy:

$$C_{\text{last}}\le r_j \quad \forall j \text{ nezaplánované}$$

pak minulost už nelze zlepšit. Aktuální uzel se bere jako nový kořen podproblému.

**3. BRTP optimality test**

![[Assets/KO/Bratley-2.png]]

BRTP je blok na konci rozvrhu, který začíná v release time první úlohy a běží bez idle time. Pokud takový blok splňuje podmínky Bratleyho testu, aktuální rozvrh už nelze zkrátit a hledání může skončit.

# Minimalizace váženého součtu dokončení

## `1 || ΣCj`: SPT

SPT znamená **Shortest Processing Time first**:

$$p_{[1]}\le p_{[2]}\le \cdots \le p_{[n]}$$

Krátké úlohy jdou první, protože jinak by zbytečně čekaly za dlouhými. Exchange argument: pokud $p_a\le p_b$, pořadí $a,b$ má součet dokončení menší nebo stejný než $b,a$.

Složitost je $O(n\log n)$ kvůli třídění.

## `1 || ΣwjCj`: WSPT

WSPT, neboli Smithovo pravidlo:

$$\frac{w_{[1]}}{p_{[1]}}\ge \frac{w_{[2]}}{p_{[2]}}\ge \cdots \ge \frac{w_{[n]}}{p_{[n]}}$$

Úloha s vysokou vahou a krátkým časem má nejvyšší "užitek za jednotku času", proto jde dopředu.

Exchange argument pro dvojici $a,b$ dá podmínku:

$$w_a p_b \ge w_b p_a$$

což je ekvivalentní:

$$\frac{w_a}{p_a}\ge \frac{w_b}{p_b}$$

## Kdy se jednoduchá pravidla rozbijí

Release times mění situaci, protože procesor může čekat na budoucí krátké úlohy. Například `1|rj|ΣCj` je NP-těžké bez preempce. S preempcí se vrací polynomiální varianta: vždy zpracovávat úlohu s nejkratším zbývajícím časem.

# Branch and Bound v rozvrhování

Pro `1|prec|ΣwjCj` se používá Branch & Bound s LP relaxací jako dolní mezí. Jde o exaktní přístup pro NP-těžký problém.

## Relative-order formulace

Místo přesných časů startu modelujeme pořadí:

$$x_{ij}=1 \iff T_i \text{ je před } T_j$$

Completion time úlohy $j$:

$$C_j=\sum_i p_i x_{ij}$$

Bereme $x_{jj}=1$, aby se započítal i vlastní čas $p_j$.

Cíl:

$$\min \sum_j w_j C_j$$

Základní omezení:

- precedence: pokud $i\prec j$, pak $x_{ij}=1$,
- pro každou dvojici $i\ne j$: $x_{ij}+x_{ji}=1$,
- tranzitivita: nesmí vzniknout cyklus pořadí.

LP relaxace povolí $x_{ij}\in[0,1]$. Dostaneme dolní mez: LP může "podvádět" frakčním pořadím, proto nemůže být horší než skutečné celočíselné optimum. V B&B ořežeme větev, pokud její dolní mez už není lepší než nejlepší známé řešení.

---

# Minimalizace $L_{\max}$

$$L_{\max}=\max_j(C_j-d_j)$$

Měří nejhorší překročení due date. Kladné $L_{\max}$ znamená, že alespoň jedna úloha je pozdě. Záporné znamená, že všechny skončily před due date.

## `1 || Lmax`: EDD

EDD = **Earliest Due Date first**:

$$d_{[1]}\le d_{[2]}\le \cdots \le d_{[n]}$$

Exchange argument: pokud $d_a\le d_b$, ale $b$ je před $a$, jejich prohození nezhorší maximum lateness. Opakováním prohození dostaneme EDD pořadí.

Složitost je $O(n\log n)$.

---

# Hornův algoritmus

Hornův algoritmus řeší:

$$1|pmtn,r_j|L_{\max}$$

Je to EDF s preempcí: v každém okamžiku běží dostupná úloha s nejmenším $d_j$. Pokud přijde úloha s bližším due date, aktuální úloha se přeruší.

## Princip

Události jsou release times a dokončení úloh. Mezi dvěma událostmi se nic nemění, takže stačí rozhodovat v těchto časech.

```text
Dokud existují nedokončené úlohy:
  vezmi dostupnou úlohu s nejmenším d_j
  spusť ji do dokončení nebo do příchodu další úlohy
  pokud přijde urgentnější úloha, proveď preempci
```

Hornův algoritmus je optimální pro $L_{\max}$, protože každou lokální odchylku od EDF lze výměnou vrátit na EDF bez zhoršení největší lateness.

Složitost základní implementace je $O(n^2)$.

## Chetto-Silly-Bouchentouf

Pro variantu s precedence:

$$1|pmtn,prec,r_j,d_j=\text{ed}_j|L_{\max}$$

nejdřív upravíme data tak, aby závislosti byly zakódované v release times a deadlines.

Forward propagation:

$$r'_j=\max\left(r_j,\max_{h\prec j}(r'_h+p_h)\right)$$

Backward propagation:

$$\text{ed}'_j=\min\left(\text{ed}_j,\min_{j\prec k}(\text{ed}'_k-p_k)\right)$$

Pak se precedence odstraní a spustí se Hornův algoritmus na upravených nezávislých úlohách.

# Paralelní identické zdroje

Máme $R$ identických procesorů. Každá úloha může běžet na libovolném z nich.

| Problém | Složitost | Typické řešení |
| --- | --- | --- |
| `P \| pmtn \| Cmax` | polynomiální | McNaughton |
| `P2 \|\| Cmax` | NP-těžký slabě | DP / subset sum |
| `P \|\| Cmax` | NP-těžký slabě | LPT aproximace |
| `P \| prec \| Cmax` | NP-těžký | List Scheduling |

`P2||Cmax` je NP-těžký redukcí z 2-Partition: rozdělit úlohy mezi dva procesory se stejným makespanem odpovídá rozdělení čísel na dvě stejně velké sumy.

---

# McNaughtonův algoritmus pro `P | pmtn | Cmax`

Preempce je povolena, úlohy nemají release times ani precedence.

Optimum:

$$C^*_{\max}=\max\left(\max_j p_j,\frac{\sum_j p_j}{R}\right)$$

První člen říká, že nejdelší úloha se nedá zkrátit. Druhý člen říká, že celková práce se musí rozdělit mezi $R$ procesorů.

McNaughton tuto mez dosáhne metodou wrap-around: úlohy se kladou za sebe do řádků délky $C^*_{\max}$. Pokud úloha přeteče konec řádku, její zbytek pokračuje na dalším procesoru od času 0.

# List scheduling

List Scheduling je greedy framework pro paralelní procesory. Máme seznam úloh. Když se uvolní procesor, vezmeme první dostupnou úlohu ze seznamu.

Pro precedence používáme dostupný čas:

$$a_i=\max_{j\prec i} C_j$$

Pokud některý předchůdce ještě není zaplánovaný, úloha zatím dostupná není.

```text
List Scheduling:
  udržuj časy uvolnění procesorů
  vezmi nejdříve volný procesor
  vyber první dostupnou úlohu ze seznamu
  naplánuj ji na max(volný procesor, dostupnost úlohy)
```

Aproximační garance pro `P|prec|Cmax`:

$$C_{\max}^{LS}\le \left(2-\frac{1}{R}\right)C_{\max}^{OPT}$$

## LPT

Pro `P||Cmax` bez precedence je běžná volba seznamu:

$$p_{[1]}\ge p_{[2]}\ge \cdots \ge p_{[n]}$$

To je **LPT**. Dlouhé úlohy se rozmístí hned na začátku, malé pak vyplní mezery.

Garance:

$$C_{\max}^{LPT}\le \left(\frac{4}{3}-\frac{1}{3R}\right)C_{\max}^{OPT}$$

# Dynamické programování v rozvrhování

Rothkopfův algoritmus je pseudopolynomiální DP pro:

$$P||C_{\max}$$

Stav:

$$x_i(t_1,t_2,\ldots,t_R)=1$$

znamená, že prvních $i$ úloh lze rozdělit tak, aby procesor $k$ měl zatížení $t_k$.

Inicializace:

$$x_0(0,0,\ldots,0)=1$$

Při přidání úlohy $i$ s délkou $p_i$ ji zkusíme přidat na každý procesor:

$$t_k \leftarrow t_k+p_i$$

Na konci hledáme dosažitelný stav s minimální hodnotou:

$$\min \max(t_1,\ldots,t_R)$$

Složitost:

$$O(n\cdot UB^R)$$

Je to pseudopolynomiální pro fixní $R$, ale rychle exploduje s počtem procesorů. Pro $R=2$ je to podobné subset-sum tabulce; pro větší $R$ nastává prokletí dimenzionality.

# Projektové rozvrhování s časovými omezeními

Projektové rozvrhování používá obecnější časové vztahy mezi starty úloh:

$$s_i+l_{ij}\le s_j$$

Hrana $(i,j)$ s váhou $l_{ij}$ říká, že $T_j$ smí začít nejdříve $l_{ij}$ jednotek po startu $T_i$.

## Temporální omezení

| Omezení | Zápis |
| --- | --- |
| klasická precedence $i$ před $j$ | $s_i+p_i\le s_j$ |
| minimální zpoždění $L$ | $s_i+L\le s_j$ |
| maximální zpoždění $U$: $s_j\le s_i+U$ | $s_j-U\le s_i$, tedy hrana $j\to i$ s váhou $-U$ |

Soustava temporálních omezení je přípustná, pokud se v grafu nevynutí spor typu:

$$s_i\ge s_i+\epsilon,\quad \epsilon>0$$

To odpovídá pozitivnímu cyklu v zápisu $s_i+l_{ij}\le s_j$.

## `PS1 | temp | Cmax`

Jeden zdroj + temporální omezení je NP-těžký. Obsahuje jako speciální případ `1|rj,edj|Cmax`.

Převod přes dummy úlohu $T_0$ se startem 0:

- release time $r_j$: hrana $T_0\to T_j$ s vahou $r_j$,
- hard deadline $\text{ed}_j$: podmínka $s_j+p_j\le \text{ed}_j$ přepsaná jako hrana $T_j\to T_0$ s vahou $p_j-\text{ed}_j$.

## `PSm,1 | temp | Cmax`

Máme více dedikovaných zdrojů, každý kapacity 1. Úloha má pevně daný zdroj.

Převod na jeden virtuální zdroj:

- každému zdroji dáme časové okno délky $UB$,
- zdroj $k$ posuneme o $(k-1)UB$,
- start úlohy na zdroji $a_i$ transformujeme:

$$s'_i=s_i+(a_i-1)UB$$

- temporální omezení se posune:

$$l'_{ij}=l_{ij}+(a_j-a_i)UB$$

Výsledkem je jedna dlouhá časová osa s upravenými omezeními.

# ILP formulace rozvrhovacích úloh

Pro `PS1|temp|Cmax` se používají hlavně dvě formulace.

## Time-indexed model

Proměnná:

$$x_{it}=1 \iff T_i \text{ začíná v čase } t$$

Každá úloha začne jednou:

$$\sum_t x_{it}=1$$

Start:

$$s_i=\sum_t t x_{it}$$

Temporální omezení:

$$s_i+l_{ij}\le s_j$$

Kapacita zdroje: v každém čase běží nejvýše jedna úloha.

Výhody:

- přirozená kapacitní omezení,
- jednoduché pro malé časové horizonty,
- počet proměnných je $O(n\cdot UB)$.

Nevýhoda: model roste s časovým horizontem $UB$.

## Relative-order model

Proměnné:

$$s_i,\qquad x_{ij}=1 \iff T_i \text{ je před } T_j$$

Pro každou dvojici na stejném zdroji musí platit jedno z pořadí. Typicky se používá Big-M:

$$s_i+p_i\le s_j+M(1-x_{ij})$$

$$s_j+p_j\le s_i+Mx_{ij}$$

Výhody:

- počet proměnných je $O(n^2)$,
- nezávisí přímo na $UB$,
- vhodné pro velký časový horizont a menší počet úloh.

Nevýhoda: Big-M oslabuje LP relaxaci, pokud je $M$ příliš velké.

## Srovnání

| Model | Proměnné | Silná stránka | Slabina |
| --- | --- | --- | --- |
| Time-indexed | $O(n\cdot UB)$ | jednoduchá kapacita | roste s časem |
| Relative-order | $O(n^2)$ | nezávisí na UB | Big-M, slabší relaxace |
